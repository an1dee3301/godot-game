# Baggage Panic

A 3D endless runner set inside an airport baggage system. You play a runaway suitcase on three conveyor belts: change lanes, jump broken rollers and low security gates, flatten under X-ray scanners, collect travel items, and follow the right destination. The game is built for **Godot 4.8** with the **GL Compatibility** renderer and GDScript.

## Run

Open [project.godot](project.godot) in Godot 4.8 and press **F5**. The start board explains the rules; choose **START** or press **Enter**. The suitcase moves forward automatically. A windowed command-line run also works:

```sh
godot --path .
```

No asset download, plugin, network connection, or setup step is needed. The scene, models, materials, UI, sound effects, and music are generated by the project; the only data file is the bundled Natural Earth land outline used for the world maps (see [Assets and references](#assets-and-references)).

## Controls

| Key | Action |
| --- | --- |
| A / Left arrow | Move one belt left |
| D / Right arrow | Move one belt right |
| W / Up arrow / Space | Jump |
| S / Down arrow / Shift | Flatten and slide |
| Esc / P | Pause or resume |
| Enter | Start or restart from the relevant menu |

You can also use the menu buttons. Jump clears low security gates and belt gaps; flattening clears the overhead X-ray scanner. Tall suitcases, carts, and the route divider require a lane change. Falling through broken rollers ends the run.

## Playing a run

The first two belt chunks let you practise the controls. The suitcase then enters randomly chosen airport zones. Watch the floor for yellow gap edges, read the overhead route signs at forks, and use the HUD destination code to choose the correct exit. The run continues until a hazard hits the unshielded suitcase or it falls.

The departure-board HUD keeps the immediate decisions visible:

- **Score and distance** rise as the conveyor carries you forward.
- **Level and speed** show the current pace.
- **Tags and weight** show the reward and cost of collecting luggage.
- **Destination** tells you which fork exit to take.
- **Shield and boost** show whether a sticker is active and how long boost remains.

After a loss, the game-over board reports the cause, score, distance, tags, level, correct and wrong routes, and personal best. Press Enter or use **RESTART** to begin a new generated run. Esc opens a pause board with resume, main menu, and quit options.

| Animations | Procedural `AnimationPlayer` tracks cover idle, run, jump, slide, hit, and death. The suitcase also has lane lean, shield and boost effects, and a death lid/clothes effect. |

### Track and fairness

The first two segments are safe. After that, the generator places obstacle rows with at least one passable lane and reserves a checkpoint every sixth segment. Each chunk begins where the previous one ends. [`TrackManager._spawn_to_horizon`](scripts/track/track_manager.gd) keeps about 230 m ahead; [`TrackManager._physics_process`](scripts/track/track_manager.gd) frees chunks more than 25 m behind. A rolling history discourages repetition, and split conveyors are limited to one in any four segments.

| Segment | What changes in the airport |
| --- | --- |
| Straight | Transfer belts with mixed obstacle rows |
| Scanner | X-ray screening and slide-focused rows |
| Luggage pile | Oversize luggage and blocked lanes |
| Split conveyor | Two destination exits with a central divider |
| Moving suitcase | Luggage that shifts across belts |
| Carousel | Claim-area scenery and luggage obstacles |
| Maintenance tunnel | Broken roller gaps and service fixtures |
| Loading bay | Luggage carts, gates, and loading scenery |
| Start / checkpoint | Intro space / customs trigger with a weight payout |

Inside these zones, [`SegmentLibrary._pick_pattern`](scripts/track/segment_library.gd) chooses obstacle-row combinations such as single blocks, double blocks, zigzags, jump walls, scanner walls, and gap rows. The chooser weights complex rows more strongly at higher difficulty. This provides variation within each of the eight regular segment types.

[`TrackSegment.build_belts`](scripts/track/track_segment.gd) creates the three physical belt surfaces. Maintenance gaps omit floor in one lane, so a miss causes a fall. The hazard builder gives low gates a jump height, overhead scanners a slide height, and tall obstacles a lane-switch role. The player uses a `CharacterBody3D` for floor motion and a child `Area3D` hitbox for hazards, pickups, and triggers.

Hazard rows are separated by at least the current difficulty's row spacing. When the safe lane changes, the builder also reserves travel time for the switch. Gap lengths are capped against speed and jump reach. The fork sign appears before the divider, giving time to choose a side. [`tests/track_fairness_test.gd`](tests/track_fairness_test.gd) samples seeded builds at four distances to check these structural properties.

### Score and original improvements

Distance earns one point per metre. Tags add 10 and passports add 50; both add weight. At maximum weight the suitcase moves 30% slower. A checkpoint awards `round(weight × 500)` points and clears that weight. Priority and Fragile stickers each add 25 points when picked up.

| Feature | Player-facing effect | Code |
| --- | --- | --- |
| Fragile Sticker Shield | Absorbs one hazard hit, breaks visibly, and lets the run continue. A fall still ends the run. | [`PowerUps.consume_shield`](scripts/core/power_ups.gd), [`RunnerMain._on_hazard_hit`](scripts/main.gd) |
| Priority Luggage Boost | Six seconds of 1.35× speed and 2× score, with a visible trail and HUD timer. | [`PowerUps.give_boost`](scripts/core/power_ups.gd), [`RunnerMain._physics_process`](scripts/main.gd) |
| Wrong Destination Gates | A split belt shows two airport codes. Match the current HUD destination for +150; the wrong exit costs 10% of the current score and adds weight. The destination then changes. | [`SegmentLibrary.build`](scripts/track/segment_library.gd), [`RunnerMain._on_trigger_entered`](scripts/main.gd) |
| Weight and checkpoints | Collecting tags and passports weighs the bag down; customs checkpoints bank a weight bonus and restore speed. | [`RunnerMain._on_pickup_collected`](scripts/main.gd), [`RunnerMain._on_trigger_entered`](scripts/main.gd) |
| Local high score | The best score survives restarts and future launches in `user://baggage_panic_save.cfg`. | [`SaveData`](scripts/core/save_data.gd) |
| Procedural sound and music | Synthesized movement, pickup, route, shield, level, and death cues plus a loop whose pitch rises with difficulty. | [`SoundFX`](scripts/audio/sound_fx.gd) |
| Rush hour lighting | Terminal light, fog, alarm pulses, and music intensity change as distance increases. | [`AirportEnvironment.set_intensity`](scripts/world/airport_environment.gd), [`SoundFX.set_music_intensity`](scripts/audio/sound_fx.gd) |

The score multiplier applies to distance and pickup points during Priority Boost. Route and checkpoint bonuses are applied directly by the game controller. The HUD and game-over board show progress, route results, and the best score.

The difficulty curve is based on distance rather than a timer. Level rises every 250 m; base speed grows from 12 to 32 m/s across the curve. Obstacle density rises from 0.35 to 0.9, while row spacing trends from 14 to 7 m. This also feeds the rush hour atmosphere: warmer light, denser fog, pulsing warning lamps, and a faster music loop.

## Architecture

[`RunnerMain`](scripts/main.gd) creates and connects the systems when [`scenes/main.tscn`](scenes/main.tscn) loads. The track goes toward negative Z. Lane 0 is left, 1 is centre, and 2 is right.

The main event path is short enough to follow during a code review:

1. `BP.ensure_input_actions` registers keyboard actions when the scene starts.
2. The player reads movement input during physics updates and emits signals when its hitbox enters an area.
3. `RunnerMain` handles those signals, updates score or state, and requests sound and HUD feedback.
4. `TrackManager` supplies new chunks as the player advances, using the current `Difficulty` object.
5. The environment and audio systems receive the difficulty intensity each frame.

This division keeps the player focused on movement, the track focused on generation, and the controller focused on game rules. The project uses named physics layers so belts, hazards, and pickups have separate collision behavior.

| --- | --- |
| [`scripts/main.gd`](scripts/main.gd) | Game state, score, events, restart, and subsystem wiring |
| [`scripts/core/bp.gd`](scripts/core/bp.gd) | Shared dimensions, lane positions, physics layers, and input actions |
| [`scripts/core/difficulty.gd`](scripts/core/difficulty.gd) | Distance-based difficulty curve |
| [`scripts/core/power_ups.gd`](scripts/core/power_ups.gd) | Shield and boost state and timers |
| [`scripts/core/save_data.gd`](scripts/core/save_data.gd) | Local personal best via `ConfigFile` |
| [`scripts/player/suitcase_player.gd`](scripts/player/suitcase_player.gd) | Input, physics, collision signals, model, and six animations |
| [`scripts/player/follow_camera.gd`](scripts/player/follow_camera.gd) | Chase framing and hit shake |
| [`scripts/track/track_manager.gd`](scripts/track/track_manager.gd) | Spawn-ahead and recycle-behind lifecycle |
| [`scripts/track/segment_library.gd`](scripts/track/segment_library.gd) | Pattern selection, hazards, pickups, and route layout |
| [`scripts/track/track_segment.gd`](scripts/track/track_segment.gd) | Physical belts and missing-floor gaps |

## Test and capture

From the project root:

```sh
godot --headless --path . -s res://tests/smoke_test.gd
godot --headless --path . -s res://tests/track_fairness_test.gd
```

The smoke test checks menu and run states, movement, actions, collectibles, shield and route logic, track recycling, game over, and restart. The track fairness test checks generated patterns and safe passage. A normal engine launch can be checked with `godot --headless --path . --quit-after 30`.

The tests run as `SceneTree` scripts and print a final PASS or FAIL line. The smoke test temporarily manipulates gameplay events to cover rare pickups and forks in one run, then restores the saved high score. The fairness test builds seeded segments at 0, 500, 1500, and 3000 m and checks lane availability, spacing, gap length, fork coverage, and increasing obstacle frequency.

The screenshot script needs a graphics window. Set an output directory and run:

```sh
mkdir -p /tmp/baggage_panic_shots
BP_SHOT_DIR=/tmp/baggage_panic_shots godot --path . -s res://tests/screenshots.gd
```

It captures menu, running, jump, slide, later play, and game-over frames. The scripted capture temporarily controls the game and restores the saved personal-best file afterwards.

## Assets and references

**Third-party data (one file):** `assets/data/land-110m.json` — Natural Earth 1:110m land polygons
([naturalearthdata.com](https://www.naturalearthdata.com/), public domain), via the
[`world-atlas`](https://github.com/topojson/world-atlas) npm package (ISC licence). `tools/make_world_map.py`
rasterises it into `assets/data/world_land_mask.png`, which `scripts/world/world_map.gd` colours into the terminal's
world-map murals with great-circle routes between real airport coordinates.

Everything else — geometry, materials, flags, UI, sounds and music — is generated in GDScript from Godot primitives.

**Real-world content and its sources**
- National flags (`scripts/world/flags.gd`) are drawn from official construction specifications and colours (e.g. U.S.
  flag design guide, Indian Flag Code, PRC National Flag Law, Australian government construction diagram, Korean
  Ministry of the Interior and Safety). Canada is deliberately omitted (maple leaf not reproduced to spec).
- Airports (`scripts/world/airport_data.gd`): IATA codes, names, cities and coordinates from
  [OurAirports](https://ourairports.com/); time zones per the [IANA tz database](https://www.iana.org/time-zones). The
  terminal's world clocks show the real current local time, including daylight-saving rules.
- Fictional on purpose: the airline "Baggage Panic Air" (flight prefix `DN`; two-letter prefixes can coincide with real airline designators, no real airline is implied), its flight numbers and schedules, gate
  numbers, and the generic aircraft liveries (no real airline branding).

**Tutorial / references:** no tutorial project or code was used; the game was designed and written for this assignment.
API reference: [Godot documentation](https://docs.godotengine.org).
